# 检索质量评测报告

## 实验设置

- **数据集**：10 组 ground-truth Q&A（基于 vault 真实笔记，含 question / expected_answer / relevant_notes）
- **指标**：
  - `Recall@5`：top-5 结果中命中至少一个相关笔记的查询比例
  - `平均命中/查询`：每个查询平均命中几个相关笔记
- **对比策略**：纯向量 / 纯 BM25 / 混合 RRF / 完整管线（+图谱扩展）

## 结果

| 策略 | Recall@5 | 平均命中/查询 |
|------|---------|--------------|
| 纯向量 (Vector) | 90.0% | 1.10 |
| 纯 BM25 (Keyword) | 80.0% | 1.50 |
| **混合 RRF** | **100.0%** | 1.30 |
| **完整管线 (+图谱扩展)** | **100.0%** | 1.30 |

> 运行：`python tests/rag/ablation.py`

> ⚠️ 数据时效：下表为最近一次消融运行的快照。检索管线（embedding 模型 / 分块 / reranker）若有改动，请重跑 `ablation.py` 更新本表。

## 关键结论

1. **混合检索（RRF）把 Recall 从 90%/80% 提升到 100%** —— 这是"为什么用混合检索"的直接证据。

2. **向量 vs BM25 的互补性**：
   - BM25 平均命中更高（1.50 > 1.10），但 Recall 更低（80% < 90%）—— 关键词检索"广撒网"，但遇到词不匹配的查询会整体 miss（如"配置 Nginx 反向代理"漏掉"SSL"这类语义相关但词不同的笔记）
   - 向量检索"准而稳"，但聚焦（平均命中少）
   - 两者 RRF 融合后取长补短，Recall 达到 100%

3. **图谱扩展在 Recall@5 层面无额外提升**（top-5 已命中），但它在对话场景提供额外上下文（关联笔记），对答案完整性有贡献，而非检索命中率。

## 面试叙事

> "我做了一个消融实验：同一批 10 个 ground-truth 问题，纯向量检索 Recall 90%，纯 BM25 80%，混合 RRF 后 100%。这证明技术笔记场景下，纯向量会漏掉精确术语匹配（`AST`、`MCP`），纯关键词抓不住语义，只有混合检索才能取长补短。"
